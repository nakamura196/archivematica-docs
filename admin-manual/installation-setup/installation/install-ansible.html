Ansibleを使った自動インストール¶

Ansible を使ったソースからのインストールは、Ubuntuへの新規インストールに適した方法です。

ここでは、ホスト・オペレーティング・システムがUbuntuであると仮定しています。これは、Mac OS XやRocky Linuxのような他のLinuxディストリビューションのような、異なるUnixベースのオペレーティングシステム用に変更できます。

ここで参照しているAnsibleロールは、独自のAnsibleプレイブックを作成して実行することで、生産環境でのデプロイで使用できます。詳細は、 deploy-pub repoを参照してください。

インストール方法¶

注釈

これらの手順は、pipのようなPythonパッケージマネージャーがシステムにインストールされていることを前提としています。pipから、リリースされたバージョンのAnsibleをインストールできるはずです。

重要

ArchivematicaをElasticsearchなしでインストールしたい場合、 またはElasticsearchの機能を制限してインストールしたい場合は、まずロール変数 archivematica_src_search_enabled を利用可能な値のいずれかに変更する必要があります。ArchivematicaのAnsibleロールの詳細については、 ansible-archivematica-src repoを参照してください。

  1. VirtualBox、Vagrant、Ansibleをインストールします。

    sudo apt-get install virtualbox vagrant
sudo pip install ansible==2.9.10 jmespath jinja2==3.0.3

    Vagrantのバージョンは1.9以上でなければなりません。バージョンを確認してください：

    vagrant --version

    最新版でない場合は、 Vagrantウェブサイト からダウンロードできます。

  2. デプロイレポートをチェックアウトします：

    git clone https://github.com/artefactual/deploy-pub.git

  3. Ansibleのロールをダウンロードします：

    cd deploy-pub/playbooks/archivematica-jammy
ansible-galaxy install -f -p roles/ -r requirements.yml

  4. 仮想マシンを作成し、プロビジョニングします：

    vagrant up

    警告

    これにはしばらく時間がかかります。お使いのコンピュータにもよりますが、1時間程度かかる場合もあります。Archivematicaのプロビジョニング中は、コンピュータの動作が非常に遅くなる可能性があります。Archivematicaのビルド中は、作業を保存し、コンピュータから離れるようにしてください。

    エラーがある場合、VMを再プロビジョニングすることで問題がよく解決されます。

    vagrant provision

  5. プロビジョニングが完了したら、仮想マシンにログインできます：

    vagrant ssh

    また、WebブラウザからもArchivematicaインスタンスにアクセスできます：

    • Archivematica： ` <http://192.168.168.198>`_ .

    • Storage Service： ` <http://192.168.168.198:8000>`_ .

    認証情報は、 vars-singlenode-1.15.yml にあります。

開発ブランチをデプロイ¶

前のセクションでは、Archivematicaの最新の安定版リリースをデプロイする方法を説明しました。

当社のAnsibleロールは、開発ブランチのデプロイにも使用できます。例えば、製品の品質保証(QA)を手伝っていただける場合です。

deploy-pub を使って、リファレンス・プレイブックをホストしています。次の手順に従ってください：

  1. requirements-qa.yml で定義されているロールをダウンローします：

    cd deploy-pub/playbooks/archivematica-jammy
ansible-galaxy install -f -p roles/ -r requirements-qa.yml

  2. singlenode.yml を更新して vars-singlenode-qa.yml をロードします。 pre_tasks セクションで、タスク include_vars を以下のように更新します：

    - include_vars: "vars-singlenode-qa.yml"
  tags:
    - "always"

  3. デプロイするブランチが決まっている場合や、その他のカスタム設定が必要な場合は、必要に応じて vars-singlenode-qa.yml を更新してください。デフォルトでは、 qa/1.x （Archivematica）と qa/0.x （Storage Service）のブランチからデプロイします。

  4. 新しい設定をデプロイします。Vagrantを使っている場合は、次のように実行してください：

    vagrant provision
